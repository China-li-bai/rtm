# 边界声明位的表达规范（kind=boundary）

> 适用：任何「业务环节真实存在、但刻意不由 AI 承担」的能力位。
> 首例：`overall-flow.json` 的 a6「对账不由 AI 承担」（2026-10-08）。
> 关联：方案《AI专项方案v2.docx》1.5 建设范围边界 ｜ `knowledge/product/商城AI需求追溯矩阵.md` 范围边界表。

## 一、为什么需要这个形态

汇报场景里，"不做"比"做了"更难表达。三种常见错误做法：

| 错误做法 | 后果 |
|---|---|
| 直接删掉该节点 | 画布出现空列，读作"漏画了"；业务链断了一环，反而要解释 |
| 复用 `kind: "dashed"` | **虚线在 UI 惯例里 = 占位/待补/未实现**，语义正好相反 |
| 保留成普通 AI 节点但文案说不做 | 与相邻 `AIP-xxx` 角标同形，视觉上主张它是 AI 能力 → 扩大承诺 |

`boundary` 的定位：**把"刻意不做"做成画布上的一等公民**，让边界本身成为可信度证据。

## 二、视觉规范（四重信号，缺一不可）

```css
.node.bnd:not(.sel) { border: 1.5px solid var(--c-gray);
  background: repeating-linear-gradient(135deg, #f6f8fa 0 6px, #e9edf2 6px 12px); }
.node.bnd .tt::before { content: "⊘"; color: var(--c-gray); }
.node.bnd .aip { color: var(--c-gray); background: rgba(255,255,255,.78); padding: 1px 5px; }
```

1. **斜纹底**——借工程图「保留区/不做区」的通用符号语言，财务与工程背景的人都认；
2. **深灰实线（非虚线）**——传达"确定不移"，与 `dashed` 的"待定"拉开语义；
3. **`⊘` 前缀**——扫描时即可识别的排除符号；
4. **角标位写「非 AI 域」**——与相邻节点的 `AIP-xxx` **同位同形**（`.aip` 同一 `right:8px/bottom:5px`），形成"有位置、无编号"的对照。这是最强的一处信号：它承认该位置在能力地图上存在，只是不挂 AI 编号。

> 实现坑：所有背景/描边必须写在 `:not(.sel)` 内。`.node.bnd` 与 `.node.sel` 特异性相同（两类），后声明者胜——不加 `:not(.sel)` 会导致选中态变不回橙色。

## 三、文案三段式

### 盒内（宜短，w=117）
- `title`：直接给结论，**主语是"谁不做"**——`对账不由 AI 承担`（勿写"对账（待评估）"）
- `sub`：两段各 ≤8 字，给替代方案——`规则判定<br>系统直连解决`
- `aip`：固定 `非 AI 域`（不含 "AIP" 字样，不触发编号格式校验）
- `panelTitle` / `panelAip`：全称与真实归属——`履约对账 · 范围边界（非 AI）` / `SHOP 履约域 + 底座规则引擎`

### 抽屉（七问框架，复用但语义翻转）
- `solves.ref` 挂**约束**而非场景：边界是约束的产物，首例挂 `C3`（AI 可幻觉·必须可审计）
- `whyAi`：**承载"为什么刻意不用 AI"**——标签仍是"为什么用 AI"，内容反问式作答，读起来有力（"这一环刻意不用 AI：……"）
- `risks`：**必须给足反面论证**，至少三条且每条配 guard：
  1. 组织压力型——"业务方要求也挂个 AI 显得智能" → 用可审计性替代 AI 标签；
  2. 风险后果型——"幻觉直接进财务链路" → AI 零调用、异常挂起；
  3. 未来回潮型——"OCR 成本下降后重提" → 不默认纳入，须先补 SOW 功能点与需求卡。
- `beforeAfter`：**必须留空**（见下节红线）
- `metrics`：收益全部走这里，并在措辞上标明执行者是系统/规则而非 AI
- `highlights`：把边界讲成价值——`边界即交付：能规则判的不交给 AI，是本方案可信度的来源`

### 页级（不看节点也要接收到）
- `subtitle`：主线叙事后追加例外声明（`⊘ 斜纹位是刻意不做的边界声明——……不冒充 AI 能力`）。**同时修掉"每个能力都向上服务"这类绝对化表述**，否则与无连线的边界位自相矛盾。
- `metricNote`：页尾口径说明追加一句"⊘ 斜纹位不是遗漏项"，并引用方案边界条款号。

## 四、红线

1. **非 AI 环节禁用 `beforeAfter`**：面板表头固定为「使用 AI 前 / 使用 AI 后」，把系统或规则改造的收益放进该列等于冒充 AI 收益。收益一律走 `metrics`。此坑只有 DOM 实测能发现，纯文案审查看不见。
2. **不得挂 `AIP/AICS` 编号**：角标必须能在 SOW 功能清单里同义对上，否则是扩大承诺（参 `00-功能点总索引.md`「勿在演示中扩大承诺」）。
3. **不得用"待补充/规划中/暂缓"类措辞**：那是 `dashed` 的语义，混用会让读者以为排期问题。
4. **必须答得出"如果硬用 AI 会怎样"**：答不出就还不是一个真正的边界决策，只是没做。

## 五、新增一个边界位的成本

schema 枚举、`NODE_DEFAULT_H`、`NodeBox` 分发、`theme.css`、`MiniMap` 灰底五处**已就绪**；`predictNodeH` 对未知 kind 走通用内容预测路径，几何自动适配。新增边界位只需在场景 JSON 里配 `kind: "boundary"` + 上述三段文案，无需再改代码。

## 六、验证方法

DOM 实测四件套（截图只能确认观感，不能确认语义）：
- `getComputedStyle(bnd).borderTopStyle === 'solid'` 且 `backgroundImage` 含 `repeating-linear-gradient`
- `getComputedStyle(tt,'::before').content === '"⊘"'`（注意伪元素挂在 `.tt` 上，查盒体会误判为 `none`）
- 角标与相邻 AI 节点的 `right/bottom` 偏移一致（scale 后 ±1px 属取整噪声）
- 点击后 `backgroundColor` 变回 `accent-soft`、描边回到 accent 2px（验证 `:not(.sel)` 生效）
