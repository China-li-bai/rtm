# 流程图自动布局与正交布线方案

> 场景：泳道流程图节点增多后，手工坐标导致长斜线跨泳道、虚线穿层、回环贯层、分支标签压线。
> 结论：**布局与布线是两类问题，交给两个专业库；构建期运行、运行时零增量。**
> 2026-10-10 任务AC 更新：GRID_GAP 纠错（40→30）、edge id/routeRole/routingObstacle 契约、几何硬门禁、crossing 基准结论、运行命令（见文末新契约以下各节）。

## 选型（GitHub 成熟方案，不造轮子）

| 职责 | 库 | 来源 | 许可证 |
|---|---|---|---|
| 节点定位（layered 分层布局） | elkjs | Eclipse ELK 的 JS 移植，Sprotty 生态标配 | EPL-2.0 |
| 正交避障布线 | obstacle-router | libavoid（Adaptagrams, Monash University）的纯 TS 移植 | LGPL-2.1，零依赖 |

两库均为 **devDependency，构建期经 tsx 运行，不进 vite 产物**——单文件产物体积零增长，守住零安装红线。

## 四段管线

1. **每泳道独立 ELK layered（RIGHT 方向），只定位不喂边**；`flow.chain` 声明后走链式分支（列=链位、跨泳道同列、bar 独占行、非主链节点显式 col）
2. **泳道垂直堆叠 + 网格重排**：固定网格间隙（GRID_GAP=30，`src/flow/tokens.ts` 唯一事实源），按文案预估回写节点高度
3. **obstacle-router 全部边一次性正交避障**（路线按唯一 edge id 索引）
4. **回写 route / labelAt**：标签沿水平段自动滑动避障

## 关键坑（探针实证，非推测）

### 1. ELK 无连边图忽略全部间距参数
不向 ELK 喂边时，`spacing.nodeNode` / `nodeNodeBetweenLayers` / `baseValue` 全部不生效，
节点间隙恒为 20px === 双侧 shapeBuffer(10×2)，正交走廊被封死，布线器报 "Path not found"。
→ 布局阶段不喂边，间距由后续网格重排保证。

### 2. libavoid 路由器的晚绑定 helper
`new Router(OrthogonalRouting)` 后必须手工挂 5 个内部 helper，否则布线结果退化：
`_generateStaticOrthogonalVisGraph`、`_improveOrthogonalRoutes`、
`_ConnectorCrossings`、`_AStarPath`、`_vertexVisibility`。

### 3. ShapeRef / ConnRef 不可赋 .id
赋值会覆盖库内部 `id()` 方法导致 TypeError。
库 dist 内部导入不带 `.js` 扩展名，Node 直接跑不了，**只能用 tsx 运行**。

### 4. 引脚必须关闭独占
流程图语义下同一边界端口天然多入多出。每节点 4 pin（顶/底/左/右）：
`pin.setExclusive(false)` + visDirs 全部 `ConnDirAll`。
端口选择用启发式：跨层边按泳道层增减走"底出顶入/顶出底入"；同层按 x 差走左右。

### 5. skipLibCheck 挡不住跨文件结构检查
obstacle-router 各 d.ts 声明的内部 IRouter/IShape/IObstacle 互相缺成员，
`skipLibCheck` 只跳过库文件内部检查，不覆盖跨文件兼容性。
→ 库边界定义最小结构类型，经 `unknown` 双转隔离：
```ts
const router = new Router(OrthogonalRouting) as unknown as AnyRouter & LateBoundHelpers;
```

### 6. 标签带虚拟障碍：只封文字区，留固定窄通道
跨层反哺线必须穿过泳道左侧标签带。
- **封死整条带**会把路线逼出画布（实测 minX=-10）——层内若有全宽 bar，绕行通道几何上不存在；
- **正解**：障碍左缘延伸到 -1000（杜绝绕出画布），右缘只止于层名文字区右侧，
  几何上在带右缘逼出一条 x≈113~120 的固定窄通道，所有反哺竖线归束于此。
- 虚拟障碍只注册 ShapeRef，不建 pin、不渲染。

### 7. 标签定位：沿段滑动 + 安全膨胀
只取"最长水平段中点"会让标签贴着节点（实测与菱形仅 1px 间隙，视觉粘连）。
→ 节点矩形按 6px 安全间隙膨胀后再做相交判定；标签从中点起以 2px 步长双向滑动，
首个不相交位置即采用；长段放不下再依次尝试更短水平段。

## 确定性校验优于截图目检
- **折点×节点矩形严格内部相交**检测穿框；
- **节点两两矩形重叠**检测压盖；
- **标签框×膨胀后节点矩形**检测标签压线。
每次布局后跑几何校验器，比人工截图可靠且可重复。

## 新契约：edge id 与 routeRole（2026-10-10 任务AC）

- `flow.edges[].id` **必填且全文件唯一**（schema 强制）：路线 Map 键与报错定位都用它，
  允许同 from→to 存在多条平行边。14 份配置已由 `review/repair-edge-id-role.ts` 一次性回填（`e-${from}-${to}`）。
- `flow.edges[].routeRole`（默认 `primary`）：业务路由角色，与视觉 `style` 正交——
  `primary` 主链 / `branch` 条件分支 / `feedback` 回前序 / `support` 数据支撑。
  **禁止从 style 推导角色**（虚线既可能是分支也可能是反馈线）。当前仅 ai-chat-guide 21 条边人工显式标注，其余场景吃默认值。

## 新契约：bar 是否为路由障碍（routingObstacle）

- 缺省：**所有节点（含 bar）都是障碍**——多数场景的 bar 是真流程枢纽（service-faq f8 五入一出、cat-governance g7 有出边反馈）。
- 纯装饰/能力横条（sink 型，如 ai-chat-guide bar1「会话留痕」）显式置 `"routingObstacle": false`：
  不注册 ShapeRef、连线允许从其视觉带内穿过；挂接边端点经 `ConnEnd.fromPoint` 按「面向对端 + 横条感知」贴边接入
  （横条几何中心无意义，一律上/下边贴接、落点在对端中心正下方），不产生沿横条内部穿行的刺线。
- 教训（g5→u3 越界根因）：全宽 bar 障碍 + 右缘无边界防护 + 平行线 nudging 三者叠加会把回连线挤出画布
  （实测 x=1370 > 画布 1360）；摘障碍后回连线走内部通道即根治（maxX=1248）。
- 否决记录：画布四向边界墙（镜像 BAND_FAR_LEFT）不可行——ai-recommend/attr-extraction 的回连线
  依赖「bar 右缘 2px 缝隙」贴边走线，边界墙（buffer 10）会把该走廊挤死导致无路可路由；
  越界 containment 由 validate 硬门禁承担。

## 几何验证器硬门禁（src/flow/geometry-rules.ts）

- **error（构建阻断）**：route 点越出画布 / 连续重复路线点 / 非正交段 / 端点不在节点边界 /
  穿非端点障碍节点 / 标签越出画布 / 标签压非关联节点 / 缺 route。
- **warn（聚合上报）**：标签压自身端点节点（存量 10 处）/ 标签互压与压非关联线 /
  边-边交叉（主链×主链单独计数；ai-chat-guide 已做到主链×主链 = 0）。
- 负向测试：`npx tsx scripts/geometry.test.ts`（14 例，含 g5→u3 回归 fixture）。

## crossing 参数基准结论（阶段2 实测，勿盲开）

`LAYOUT_CROSSING=off|low|mid` 试验开关（默认 off；low=50 / mid=150 + 主链连接器 setHateCrossings）。
2026-10-10 全量 14 份实测：**off = 1s 完成；low=50 在 contract-blueprint（33 边全部默认 primary）
上 >14min CPU 未完成**。全局开交叉惩罚在本场景集不可行，仅限小场景单文件实验，默认必须保持 off。
交叉治理走 routeRole 语义与通道约束，不靠惩罚值。

## 运行命令

```bash
npm run layout    # 构建期布局+布线，回写 scenarios/*.json（幂等：二次运行零 diff）
npm run validate  # 业务红线 + 几何硬门禁，任一 error 即 exit 1
npm run build     # layout → validate → vite build 单文件产物
npx tsx scripts/geometry.test.ts   # 几何规则负向测试
npx tsx scripts/flow-metrics.ts    # 越界/交叉/标签/长度指标报告（调参对照用）
```
