# AI 商城从 0 到 1 业务蓝图（行业对标定稿）

> 建立：2026-10-05 ｜ 用途：overall-flow 场景页（商城 AI 业务全景·从 0 到 1）的业务口径事实源
> 检索基线：六组行业检索（通用电商链路 / B2B P2P / Amazon AutoKnow / 阿里京东中台 / Shopify Magic / AI 客服导购）

## 一、行业对标（我们的每个业务段都有头部对应物）

| 业务段 | 行业对应物 | 对标要点 |
|--------|-----------|---------|
| 招商推品 | SRM 供应商准入 / S2B2b 集采商城（万米商云等） | 供应商全生命周期：准入→资质→合同→推品协同 |
| 治理上架 | **Amazon AutoKnow**（KDD 2020） | 自驱动商品知识收集：taxonomy 构建 + 属性发现抽取 + 清洗集成——我们的类目挂载+属性抽取+校验同构 |
| 标准商品池 | 阿里业务中台·商品中心（大中台小前台） | 商品能力沉淀为中台资产，多前台复用（一池多用） |
| 搜索发现 | 淘宝 AI 万能搜 / 京东「搜索-比价-看规格-下单」AI 化 | 搜索是 AI 主战场：语义召回+筛选面板；复杂语义相关性提升（淘天 20 个百分点口径） |
| 比价决策 | B2B 寻源询比价（SRM sourcing / 询比价采购） | 询价单→多报价对比→定标；我们=同款簇一键横向比价 |
| 下单交易 | B2B P2P（SAP Ariba / Odoo procure-to-pay） | requisition→PO→支付，合规内控嵌入下单 |
| 履约对账 | **三单匹配 Three-Way Matching**（SAP GR-Based IV / Odoo） | PO↔收货单↔发票三向匹配是对账内控行业标准 |
| 售后客服 | **阿里 AI 店小蜜（AI+人）** / 京东京小智·言犀 | 售前售后全流程客服智能体；京小智单日接待超 547 万人次（2020 双11 口径） |
| 数据飞轮 | 淘天 20 亿商品 AI 精准理解 / 评测门禁 | 行为回流驱动词库/排序/知识库生长，逐版基线对比 |

## 二、从 0 到 1 八步业务主线（业务在前、AI 在后）

供给侧（把货变标准）→ 需求侧（让采购买对）→ 履约服务（闭环兑现）：

```
01 招商推品 → 02 治理上架 → 03 商品池   ║ 供给侧终点：商品「有且标准」
04 搜索发现 → 05 比价决策 → 06 下单交易 ║ 需求侧：GMV 在这里产生
07 履约对账 → 08 售后客服               ║ 服务出口：复购从这里开始
09 数据回流飞轮（横贯全链，反哺词库/模板/阈值）
```

## 三、AI 服务映射（每个 AI 的上级业务——本蓝图的核心理念）

| AI 服务 | 编号 | 上级业务（服务谁） | 关键供给 |
|---------|------|------------------|---------|
| 图文审核 | AIP-007/009 | 02 治理上架 | 入库前合规拦截 |
| **属性治理·抽取** | AIP-003~014 | **02 治理上架 → 04 搜索发现 / 05 比价决策** | **标准筛选属性（搜索筛得出来、比价拉得出单的原料）** |
| 语义检索·导购 | AIP-015~031 | 04 搜索发现 | 双路召回+一句话直搜 |
| 同款归并 | AIP-010 | 03 商品池 / 05 比价决策 | 同款簇与横向报价单 |
| 集采合规引擎 | AIP-014 | 06 下单交易 | 三卡点实时拦截 |
| 单据·三单匹配 | 对账域 AI | 07 履约对账 | OCR+三单自动匹配 |
| 智能客服 | AICS-010~025 | 08 售后客服 | 接待+转人工闭环 |

> 红线：任何 AI 功能页必须答得出「服务于哪条上级业务」（flow.bizContext 字段承载，校验口径见场景 schema）。
