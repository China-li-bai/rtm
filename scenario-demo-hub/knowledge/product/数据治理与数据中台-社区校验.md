# 数据治理与 AI 数据中台 · 对照脚手架和社区做法

> 2026-10-14。对象：商品数据治理、AI 数据中台，以及总图上的治理出口、属性抽取页里的类目树口径。对照的是正在开发的 `ai-platform-scaffold`（治理服务、数据层说明、2026-10-11 起不再回装旧类目表），以及商品主数据的常见做法：类目—属性—值是基准，品牌先于规格，规范标题是属性的产出，索引、向量、图谱、评测集是同一份合格主数据的并列投影。

## 和实现、社区做法冲突的地方

商品治理页原来把规范标题排在属性抽取前面，又把品牌归一排在抽取后面。脚手架里一条商品的顺序是：挂到类目叶子，用品牌库剥掉标题前缀，再抽规格和型号，然后校验。规范标题用的是已经校验过的属性，同款簇用的是同一批属性，这两件事不互相喂。

类目治理那一格还把「工作树 13,646 / 23 域对齐中」写成进行中。2026-10-11 起这张旧表不能再当装载源，装上会把合同标的保利树回滚。正式树是 7,141 节点、6,495 叶、13 域。

资产入池写成治理完成就自动刷新 ES 和 Milvus。嵌向量按次收费，向量消费是按需任务；Milvus 检索代码已退役，物理集合还在。治理层交出的是 clean / review / quarantined，投影在数据中台。

数据中台原来是九步串行：索引、向量、图谱、评测集、脱敏一个接一个。合格主数据通过质量门禁之后，这四份资产分头投影。脱敏是模型出域的横向闸门，不排在评测集后面。字段级血缘还没有，Dagster 只记管道资产之间的依赖。飞轮回流的是候选，人审后才进词库和评测集，不直接改主数据。

「12 类系统集成」是商城四端的对接范围，不是这条数据链要做的事。接入只纳管商品推品、订单和行为日志。

## 页上现在怎么读

| 页 | 现在的顺序 |
|---|---|
| 商品数据治理 | 类目树、属性模板、标准字典 → 挂载、品牌、抽取、校验 → 规范标题与同款并列，再入池 |
| AI 数据中台 | 接入、正源、质量门禁，然后索引 / 向量 / 图谱 / 评测集四路并列。出域脱敏单独一格，不从评测集连过来。飞轮回到正源，边上写明人审 |
| 总图治理出口 | clean 之后才投影。已有的 176,074 条向量不是每一批治理的必经一步 |
| 属性抽取页 | 类目口径只保留保利树，不再写工作树对齐中 |

预测精度 80.4% 留在「类目挂载」，不写在维护类目树的那一格。Iceberg 仍未启用，页上不把它写成已交付能力。
