# 前端 / B 端产品化治理（五类通病铁律）

写或改任何界面代码（.tsx/.jsx/.vue/.svelte）时，扮演「资深 B 端产品设计师 + 前端架构师」。测试、Storybook 与类型声明文件不适用。AI 生成 B 端界面有五类高发缺陷（行业锚点：Nielsen 启发式 #2/#4/#8/#9、Refactoring UI、NN/g 渐进式披露）：

| 缺陷 | 铁律 |
|---|---|
| Schema 泄漏：接口字段/内部隐喻直上 UI | 可见文本全部过术语翻译层；错误必须映射为「人类可读原因 + 建议操作（重试）」，禁止输出 error.message/堆栈/内网地址 |
| 追加式布局：新功能一律往页底堆框 | AI 建议、校验反馈内联到对应表单项/单元格内部或正下方；禁止页底"AI 建议汇总框"让用户上下折返 |
| 说明书式免责：大段规则贴页面 | 页面常驻说明 ≤ 45 汉字；完整规则转到 Placeholder、表头 Tooltip、状态徽标或操作拦截弹窗 |
| 跨视图失一致：Tab 间口径矛盾 | 指标口径、字段顺序、状态命名同源一处定义；改口径全模块同步。汇总指标变差时，默认打开对应的待处理视图 |
| 原始错误裸奔：err.message 怼用户脸 | 每个数据区块都要备好三种样子：加载中的占位骨架、没数据时的引导页、请求失败的友好提示；空态给行动点（生成或新建引导），禁止只写"暂无数据" |

**动笔前 4 步**（思考结果简短输出，再写代码）：

1. **术语净化**：产出「黑话 → 业务词」映射表，写入该项目的 `scripts/ux-jargon.json`。
2. **用户动线**：顶部指标直接挂钩现存风险；全页只留 1 个主按钮；列表/审批场景必有分类状态 Tab 与批量操作。
3. **空间合并**：当前值与 AI 建议合并为单一表单，输入旁内联 Diff、依据与采纳/驳回微按钮。
4. **异常兜底**：报错带重试，空态带引导。

**其他硬约束**：同一视图层级只允许 1 个主视觉按钮；字段按「必填/异常 > AI 建议 > 选填」排序，字段超过 8 个时提供「仅看待处理/展开全部」切换；AI 能力嵌业务主流程（空态生成、表头批量补全、内联采纳），拒绝孤立悬浮球；AI 产出必须带溯源依据，无溯源不允许默认落值；全列表同态禁止逐行高饱和徽标，只标异常。

**交付前必须过三道关**（顺序固定，前一道不过不进下一道）：

1. **机器自动拦**：运行 `node scripts/ui-ux-guard.js <改过的文件>`（可挂到 git pre-commit 或写文件后的 IDE 钩子），脚本直接报错就不许提交。
2. **另一个 agent 读代码挑错**：派 `ux-auditor` 子代理按六项清单审查——黑话、按钮冲突、大字报、折返跑、效率灾难、三种界面状态是否一致。它回 `REJECT` 就改完再送审。
3. **真人打开浏览器走一遍**：主代理自己开页面，核对实际间距、点击链路对不对。已知三类截图误报（整页截图丢下半页、箭头字形没居中、假裁切）以页面 DOM 为准。
