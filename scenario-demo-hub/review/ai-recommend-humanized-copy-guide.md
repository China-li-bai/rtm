# AI 猜你喜欢：场景文案“人味”和画面感修订指南

本修订不改变 AIP-029～031 的产品边界，也不把示例叙述伪装成已完成的用户访谈。目标是让读者在打开弹窗时，能立刻看见采购人员所处的页面、手头任务、卡住的动作，以及推荐能力真正替他省掉的步骤。

## 文案原则

1. **先出现一个具体动作。** 例如“月底打开工作台补货”“点开安全帽详情”“购物车快齐时回想配套品类”。不要一开始就说“系统缺少画像”“缺少语义召回”。
2. **用可观察的阻碍替代抽象词。** “退回搜索结果、换关键词、再逐个打开详情”比“采购效率低”更有画面。
3. **让解决方案回应原动作。** 用户原来要翻历史订单，方案就把常购清单带到工作台；原来要来回翻页，方案就在详情页提供可比较的候选。
4. **保留真实边界。** 单位历史不足就说明是冷启动；没有足够共现证据就隐藏关联区块；推荐理由必须来自实际数据；不要承诺所有推荐必然可采或一定提升转化。
5. **不写虚构的真实个案。** “典型场景”可以有画面，但不能虚构某位采购人员的真实经历、损失金额或访谈结论。

## 建议替换的三个场景

### S1 · 常买的东西，还得重新找

**卡片摘要**：月底整理补货单，常买的手套、护目镜就在历史订单里，采购人员却还是得重新搜、逐条核对规格。

**谁在做什么**：月底，采购人员打开工作台，准备补齐本单位的常购品。

**卡在哪**：他记得上次买过劳保手套，也记得大概的规格，却想不起具体 SKU 藏在哪张订单里。工作台如果只给全站热门榜，他还是得回到搜索框，从头找起。

**业务后果**：
- 补货单上的商品要逐项重搜、核规格，时间花在找回旧订单上。
- 常买 SKU 藏在历史记录里，临时接手采购的人很难顺手找到。
- 新单位没有足够的历史订单时，系统也不能假装已经了解它的采购偏好。

**解决方案**：工作台优先呈现当前单位内的高频品类和常购 SKU；有可信的复购周期统计时，再提示可能的补货时间。没有历史数据时，明确标注冷启动兜底的来源。

**解决后的变化**：常购品从历史订单走到工作台；新接手的人可以从单位采购记录开始；历史不足时如实说明推荐来源。

### S2 · 想比个相近款，还得来回翻页

**卡片摘要**：打开安全帽详情页后，采购人员想比较同规格或相近参数的备选商品，却还得返回结果页重新搜索。

**谁在做什么**：采购人员点开一款安全帽或其他具体商品，正在核对规格、价格和供货条件。

**卡在哪**：看完当前商品，他还想找一两款相近规格的商品放在一起比较；页面却没有可信的相似商品入口，只能退回搜索结果、换关键词，再逐个打开详情页。

**业务后果**：
- 为比较一两个关键规格，采购人员反复离开详情页、再回来定位。
- 同款或相近款分散在多个页面，规格差异不容易一眼看清。
- 如果推荐只因为标题相似、没核对关键属性，反而可能把不合适的商品带进比选清单。

**解决方案**：详情页以当前商品为起点，查找同款簇中的其他选项、同类目属性近邻和可用的语义近邻；过滤当前商品及无权查看的候选。

**解决后的变化**：在当前上下文查看备选项；推荐理由说明同款或属性依据；去重保留有效 SKU 差异。

### S3 · 清单差一件，系统没给下一步

**卡片摘要**：购物车里已有劳保手套，采购人员想起可能还要配护目镜；零结果页却只显示“没有找到商品”，没有下一步提示。

**谁在做什么**：采购人员正在收尾一张集中采购清单，或在检索某个商品时碰到了零结果。

**卡在哪**：清单已经快齐了，他还得靠记忆回想有没有经常一起采购的品类；而搜索无结果时，页面也没有基于历史采购关系的备选提示，只能换词再搜。

**业务后果**：
- 配套品类全靠人回忆，忙起来时容易忘记还有哪些项目需要确认。
- 为了补齐清单，采购人员又要换词搜索、切换页面，思路和操作被打断。
- 零结果页没有合理的下一步时，用户只能退出当前流程，或去其他地方继续找。

**解决方案**：购物车和零结果页读取当前单位内有足够统计依据的历史订单品类关联，生成候选；只有在数据确实支持时，才展示相应的关联理由。

**解决后的变化**：可靠关联为清单提供继续检查的线索；零结果页有合适候选时可以继续浏览；证据不足时不乱推。

## 如何验收是否“有人味”

打开每一个场景弹窗，检查读者能否在十秒内回答：

- 采购人员现在在哪个页面、正准备做什么？
- 他具体卡在哪个动作？
- 当前机制替他省掉了哪一步？
- 哪些是已有需求，哪些仍取决于数据是否存在或后续实现？

如果答案仍然只是“提高效率、优化体验、智能匹配”，就还不够具体。

## 应用方式

推荐直接使用完整脚本 `repair-ai-recommend-humanized.ts`：它同时包含结构修复、solves 重映射和这次的人味文案，不需要串行执行两份脚本。将它放到 `scenario-demo-hub/scripts/`，然后在 `scenario-demo-hub/` 中执行：

```bash
npx tsx scripts/repair-ai-recommend-humanized.ts
npm run layout
npm run validate
npm run build
```

完整脚本会更新 S1/S2/S3 场景文案、约束、节点 `solves` 和节点描述，并在写入前创建备份；不直接手工编写坐标或 route。由于节点文字长度变化，必须重跑 `npm run layout` 生成新的几何产物。如果你已经执行过上一版完整修复脚本，只希望调整文案，也可以改用 `humanize-ai-recommend-copy.ts`，但要确认场景 ID 与新版 S1/S2/S3 定义一致。
